3. **シグナルAPI使用戦略**:
   - サービスは状態を持たず、データ取得や処理のみを担当
   - コンテナコンポーネントは状態管理とサービスからのデータ取得を担当
   - 共有Storeはアプリケーション全体または機能間の共有状態を管理
   - コンピューテッドシグナルを使用したデータ変換

## 重要なパターンと設計上の好み

1. **Presentational/Containerパターン**:
   - 表示とロジックの分離を徹底する
   - Presentationalコンポーネントは純粋に表示のみを担当
   - Containerコンポーネントはデータ取得とロジックを担当

2. **Angular Signal API**:
   - 状態管理にはRxJSよりもSignalを優先する
   - Signalベースのストアパターンを採用
   - 複雑なシナリオのみRxJSを補助的に使用

3. **コンポーネント設計**:
   - 再利用可能なUIコンポーネントの作成
   - 機能ごとに明確に分離されたコンポーネント
   - 適切な粒度のコンポーネント分割

4. **コード品質**:
   - ESLintとPrettierを使用した一貫したコードスタイル
   - 単体テストによる高いコードカバレッジ
   - JSDocスタイルのコメントによる明確なドキュメンテーション
