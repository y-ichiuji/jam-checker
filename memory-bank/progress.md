## 既知の問題

1. **キャンバスリサイズ時の挙動**:
   - 問題: サイズ変更時にキャンバスの内容が一時的に消える現象
   - 原因: HTML Canvas APIの仕様（width/heightプロパティの変更でバッファがクリアされる）
   - 対応: サイズ変更直後に再描画処理を行う実装を追加済み

2. **パフォーマンス最適化**:
   - 大量のGeoJSONデータ処理時のレンダリングパフォーマンスの最適化が必要

3. **ブラウザ互換性**:
   - 一部の古いブラウザでResizeObserverが動作しない可能性がある

4. **スケーリングとズーム操作**:
   - 適切なズーム範囲の設定により解決済み（最小スケール値を1.0に設定）
   - ズーム操作のハンドリングを改善し、柔軟な拡大・縮小が可能に

## プロジェクト決定の変遷

### アーキテクチャ選択

- **最初の計画**:
  - NgModulesベースの構造
  - RxJSを主要な状態管理ツールとして使用

- **現在の計画**:
  - スタンドアロンコンポーネントアーキテクチャ
  - Angular Signalを主要な状態管理ツールとして使用
  - RxJSを補助的にのみ使用

### UI設計

- **最初の計画**:
  - カスタムCSSスタイルの作成
  - コンポーネントライブラリの使用

- **現在の計画**:
  - Tailwind CSSを使用したユーティリティファーストアプローチ
  - 必要に応じて独自のUIコンポーネントを構築

### データ管理

- **最初の計画**:
  - 直接的なAPIコール
  - コンポーネント内での状態管理

- **現在の計画**:
  - 専用のデータサービス
  - ストアパターンによる状態管理
  - Signalベースのデータフロー

### テスト戦略

- **当初の計画**:
  - 基本的なコンポーネントテスト
  - async/awaitベースの非同期テスト

- **現在の計画**:
  - Presentational/Containerコンポーネントの明確な役割分担を考慮したテスト
  - fakeAsync/tickを使用した効率的な非同期テスト
  - 高カバレッジ（80%以上）を目標とした包括的なテスト
  - Signalベースのストアパターン
  - 将来的なAPI連携を考慮したデータ構造
